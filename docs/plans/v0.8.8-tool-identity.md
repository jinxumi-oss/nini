# v0.8.8 — Tool call identity preservation

> **背景**：v0.8.7 修了"工具调用输出断开"（autoscroll 把 header 推走）。跑真实 MiniMax-M3 复杂任务时挖出 4 个相关 bug，都是**tool call ↔ tool result 的身份丢失**：
>
> - **Bug A**：并行 tool call 时 args 错配 —— sink 的 ToolCallStop 总是改 LAST ToolCall line，没有用 id 找对应的
> - **Bug B**：`runtime.rs:214` 硬编码 `AppState::new("test-model")`，忽略 `--model` 参数
> - **Bug C**：User message 太长时覆盖 status bar
> - **Bug D**：ToolResult 不带 tool name，user 无法辨认 `✓ Took Nms` 是哪个 tool
>
> 这 4 个都和"tool identity 在 TUI 完整生命周期里如何保留"相关，统一在一个 plan 里修。

## 目标

把 tool call 的 id + name 从 agent 一路贯穿到 TUI 渲染，确保：
1. 并行 tool call 的 args 不再互相覆盖
2. `--model` flag 真正生效
3. Status bar 不被超长 user message 覆盖
4. `✓ Took Nms` 显示 tool name（`✓ bash (4ms)` / `✗ read (3ms)`），让用户一眼看出是哪个 tool 的结果

## 改动清单

### Bug B — `runtime.rs:214` 硬编码 model（最小，一行修复）

**问题代码**：
```rust
// crates/nini-tui/src/runtime.rs:214
let mut state = AppState::new("test-model");
```

**修复**：把 `model` 作为 `run()` 参数传入。bootstrap 闭包再覆盖一次（让 caller 用具体 config）。

```rust
// crates/nini-tui/src/runtime.rs
pub async fn run<F>(bootstrap: F, agent_driver: AgentDriver) -> Result<()>
where
    F: FnOnce(&mut AppState),
{
    let mut state = AppState::new("test-model");  // 现状
    bootstrap(&mut state);
    ...
}

// 改成：
pub async fn run<F>(bootstrap: F, agent_driver: AgentDriver, initial_model: &str) -> Result<()>
where
    F: FnOnce(&mut AppState),
{
    let mut state = AppState::new(initial_model);
    bootstrap(&mut state);
    ...
}
```

调用方 `crates/nini-cli/src/app.rs:236` 把 `cfg.model` 透传。

### Bug A — 并行 tool call args 错配（核心修复）

**问题代码**：
```rust
// crates/nini-tui/src/runtime.rs:127-135 (AgentSink::push ToolCallStop)
AgentEventLite::ToolCallStop { id, args } => {
    if let Some(TranscriptLine::ToolCall { args: a, .. }) = Arc::make_mut(&mut s.transcript_state).lines.last_mut()
    {
        *a = args;  // ← 永远改最后一条，并行时前面的被覆盖
    } else {
        s.push_tool_call(id, args);
    }
}
```

**修复方案**：`TranscriptLine::ToolCall` 加 `id` 字段，按 id lookup。

```rust
// crates/nini-tui/src/state.rs:TranscriptLine
ToolCall { id: String, name: String, args: String, collapsed: bool }
```

`ToolCallStart` push 新行（带 id），`ToolCallStop` 按 id 找对应行更新 args，找不到才 fallback 到 push。

### Bug D — ToolResult 不带 name

**问题代码**：
```rust
// crates/nini-tui/src/rich.rs:render_tool_result
let label = if ok { "✓ " } else { "✗ " };  // 没带 tool name
```

**修复**：把 `name: String` 加进 `AgentEvent::ToolResult`、sink push、`TranscriptLine::ToolResult`、render 函数。

```rust
// crates/nini-core/src/agent.rs:AgentEvent
ToolResult { id: String, name: String, output: ToolOutput }

// crates/nini-tui/src/state.rs:TranscriptLine
ToolResult { id: String, name: String, ok: bool, content: String, collapsed: bool, duration_ms: Option<u64> }

// crates/nini-tui/src/rich.rs:render_tool_result
fn render_tool_result(name: &str, ok: bool, ...) -> Vec<RLine<'static>> {
    let label = if ok { format!("✓ {} ", name) } else { format!("✗ {} ", name) };
    ...
    if let Some(ms) = duration_ms {
        let dur_label = if ms >= 1000 { format!("{:.2}s ", ms as f64 / 1000.0) } else { format!("{ms}ms ") };
        // 改成 "✓ bash  Took 4ms"
    }
}
```

### Bug C — Status bar 被覆盖

**问题代码**：status bar 行 width 固定，user message 在 footer/pwd row 上 display 但太宽会"看起来"盖住 status text（实际是 terminal wrap 到 status 行）。

**修复**：
1. render_user_message 在多行情况下不 wrap 超宽行（在 display 时截断或缩进），保持 status row 干净
2. 或者：把 user message wrap 到 inner content area 的宽度，不溢出到 status row

最简单的修法：render_user_message 在 render 时检测 `area.width`，如果 `user_message` 的某行超过 area.width - 2 就截断 + 加 `…`。这样 user message 即使超长也只 wrap 自己的行，不挤 status。

### 同时修：render_tool_call 显示更友好

`▸ bash {"command":"...","description":"..."}` — 当前 120 字节截断后接 `…`。新版本可以让 tool name 更突出：把 name 用 bold/color，`{args}` 用 dim。

## 测试

新增 `crates/nini-tui/tests/tool_identity_e2e.rs`：

1. `parallel_tool_calls_keep_distinct_args` — 推 2 个 tool_call Start/Stop 事件，断言 transcript 里有 2 个 ToolCall 行，args 各自正确
2. `tool_result_shows_tool_name` — 推 ToolResult 事件，断言渲染包含 tool name
3. `cli_model_flag_propagates_to_status_bar` — 通过 `run(..., initial_model)` 验证 status bar 显示对应 model
4. `long_user_message_does_not_overflow_status_bar` — 80-wide 终端 + 200 字符 user message，断言 status bar 行不被 user 内容污染
5. `tool_call_id_lookup_falls_back_gracefully` — Stop 事件 id 不存在时（异常情况），fallback 到 push 新行（不 panic）

## 兼容性

- `TranscriptLine` 字段扩展是**破坏性变更** —— 但 session JSONL 是 v4 codec 会自动迁移（旧 ToolCall 行在 session reload 时降级处理）
- `AgentEvent::ToolResult` 加字段 → 所有 emit/translate 站点都要更新
