## 二、目标架构

### 5 个 sub-struct + 一个 facade

```
                        ┌──────────────────┐
                        │   AppState       │  facade (re-export 公共 API)
                        │                  │
                        │  ┌────────────┐  │
                        │  │ InputState │  │  输入缓冲（已是独立类型 InputBuffer）
                        │  └────────────┘  │
                        │  ┌────────────┐  │
                        │  │ Transcript │  │  对话历史 + transcript 状态
                        │  │  State     │  │
                        │  └────────────┘  │
                        │  ┌────────────┐  │
                        │  │ RunState   │  │  状态机：mode / pending_*/is_*
                        │  └────────────┘  │
                        │  ┌────────────┐  │
                        │  │ ModelState │  │  LLM 配置：model / provider /
                        │  └────────────┘  │  thinking_level / models_cycle
                        │  ┌────────────┐  │
                        │  │ UiState    │  │  UI 偏好 + 浮层 + 主题
                        │  └────────────┘  │
                        │                  │
                        │  Session         │  已有：nini_session::Session
                        │  TokenStats      │  已有：独立类型
                        └──────────────────┘
```

### 字段分配（具体到字段）

| Sub-struct | 包含字段 | LOC 估算 |
|---|---|---|
| **TranscriptState** | `transcript: Vec<TranscriptLine>`, `autoscroll`, `scroll_offset` | ~150 |
| **RunState** | `mode`, `status`, `pending_quit`, `pending_external_editor`, `abort_signal`, `is_compacting`, `is_auto_compacting`, `pending_next_turn_messages`, `context_window`, `context_used`, `cost_usd`, `tokens` | ~250 |
| **ModelState** | `model`, `provider`, `thinking_level`, `models_cycle`, `models_cycle_idx`, `settings_path`, `settings_snapshot` | ~200 |
| **SessionState** | `session_id`, `session`, `session_path`, `cwd`, `git_branch` | ~100 |
| **UiState** | `theme_name`, `last_diff`, `help_extended`, `close_help`, `search`, `selector`, `completion`, `debug_logging` | ~200 |
| **InputState** | `input: InputBuffer` (already separate) | — |
| **AppState (facade)** | 5 sub-structs + InputBuffer + TokenStats | ~150 |

每个 sub-struct **独立 derive(Clone, Debug)**，**不再手写 clone_for_render 的 50 行**——derive 一次性给所有字段。

### 公开 API 兼容层（关键）

为了**不破坏 13 个 importer + 所有测试**，保留 **Deref 或 getter** 让现有 `state.field` 调用继续工作：

```rust
// 方案 A：Deref 到 RunState（不优雅，因为没有 "main" sub-struct）
// 方案 B：手动 forwarding getters（要写 38 个）
// 方案 C：Deref 到所有 sub-structs（编译器不允许）
// 方案 D（推荐）：保留 `pub` 字段访问，但字段是 sub-struct

impl AppState {
    pub fn transcript(&self) -> &TranscriptState { &self.transcript }
    pub fn transcript_mut(&mut self) -> &mut TranscriptState { &mut self.transcript }
    // ... 但这会让现有 `state.transcript.iter()` 编译失败
}
```

**最终方案**：**彻底破坏性改名 + 一次性 sed 替换**。在 v0.8.1 上接受一次性改动大量文件，因为：
- v0.8.0-pre1 还没 release tag，用户基数小
- 拆分一次，永久受益
- 加字段的痛苦从 "6 文件" 降到 "1 文件"

具体做法：

```rust
// 之前：
state.tokens.input += 100;

// 之后：
state.run.tokens.input += 100;
```

13 个 importer + 6 个 test 文件 = **19 文件**用 `sed` 一次性替换。每个字段加 `.run` 或 `.model` 等前缀。

///
/// Public field access uses prefixed paths:
///   * `state.input`               — InputBuffer (edit buffer)
///   * `state.transcript_state`    — TranscriptState (chat history + scroll)
///   * `state.run_state`           — RunState (state machine + stats)
///   * `state.model_state`         — ModelState (LLM config)
///   * `state.session_state`       — SessionState (persistence + cwd)
///   * `state.ui_state`            — UiState (overlays + theme + debug)
///
/// The facade preserves all method calls (state.push_user, etc.) by
/// forwarding them to the appropriate sub-struct.
#[derive(Debug)]
pub struct AppState {
    pub input: InputBuffer,
    pub transcript_state: TranscriptState,
    pub run_state: RunState,
    pub model_state: ModelState,
    pub session_state: SessionState,
    pub ui_state: UiState,
}

//

// 报 E0277 "the trait bound `dyn T: Clone` is not satisfied"。
impl Clone for TranscriptState {
    fn clone(&self) -> Self { Self { lines: self.lines.clone(), autoscroll: self.autoscroll, scroll_offset: self.scroll_offset } }
}
impl Clone for RunState {
    fn clone(&self) -> Self {

}

impl Clone for SessionState { /* manual */ }
// UiState 需要跳过 selector: None
impl Clone for UiState {

            debug_logging: self.debug_logging,
            selector: None,  // Box<dyn> 不 Clone — 与原 clone_for_render 一致
        }

}

impl Clone for AppState {

//
// 实际拆分：TokenStats、CompletionPopup、SearchState 等子类型**可** derive Default，

impl Default for TranscriptState { /* lines: vec![], autoscroll: true, scroll_offset: 0 */ }

下放原则：
- **写入 transcript 的方法** → `TranscriptState`
- **读写 mode/status/abort 的方法** → `RunState`
- **读写 model/provider 的方法** → `ModelState`

Facade 上保留 **短别名** 转发：
```rust

    pub fn push_user(&mut self, t: String) { self.transcript_state.push_user(t) }

```

这样**外部调用方完全不需要改**——只需要改字段访问语法（`state.transcript` → `state.transcript_state.lines`）。

## 四、风险与缓解

### 风险 1：`state.transcript` → `state.transcript_state.lines` 的批量替换漏掉

**缓解**：
- Phase 0.2 先列出**所有**引用，落到 `state-refs.txt`
- Phase 2.1 的 sed 脚本跑两遍：第一遍覆盖率 check（用 grep 数替换前后），第二遍执行
- 引入 `#[deprecated]` 临时属性，把旧字段访问编译期 warn，但不强制（编译期 warning 也能 catch 漏改）

### 风险 2：clone_for_render 的语义丢失

`clone_for_render` 当前手动跳过 `selector` Box（因为 `Box<dyn>` 不 Clone）。拆分后：
- `SelectorState` 仍然 Box<dyn>，不可 Clone
- 解决方案：`UiState` 不要 derive Clone，把 selector 字段标记 `#[derive(Clone)]` 时跳过
- 或者：`UiState` derive Clone，selector 字段是 `Option<Box<...>>`——derive 会自动跳过 Box<dyn>

验证：`#[derive(Clone)]` 对 `Option<Box<dyn Trait>>` 的行为？Rust 默认 derive Clone 会在 Box<dyn> 上失败。**实际测试一下**。

### 风险 3：测试文件大量修改

预计改动文件：
- `crates/nini-tui/src/state.rs` — 巨大（1500+ 行修改）
- `crates/nini-tui/src/runtime.rs` — 中等（~30 处 `state.field`）
- `crates/nini-tui/src/commands.rs` — 中等（~50 处）
- `crates/nini-tui/src/render.rs` — 小（~20 处）
- `crates/nini-tui/src/selector.rs` — 小
- `crates/nini-tui/src/help_overlay.rs` — 小
- `crates/nini-tui/src/editor.rs` — 小
- `crates/nini-tui/src/command_palette.rs` — 小
- `crates/nini-cli/src/main.rs` — 中等（bootstrap + demo paths）
- `crates/nini-tui/tests/*.rs` — 6 个文件，每个 5-30 处

总计约 **15 文件、~300 处修改**。

**缓解**：
- 全程 single commit on a branch，合并前 100% 测试通过

### 风险 4：AppState 上的 70 个 pub 方法要分发

**缓解**：

## 九、是否拆 main.rs（顺手？）

观察到 main.rs 1636 LOC 也是个单点瓶颈。但**本次 v0.8.1 计划不拆**——理由：

1. AppState 拆分后**会顺带发现** main.rs 的某些 setter 调用可以挪到更合适的位置
2. main.rs 拆分的耦合面更复杂（涉及 CLI 解析 = clap），不能纯机械操作
3. 避免单次重构改动太大

main.rs 拆分作为 **v0.8.2 候选**，单独建计划。
