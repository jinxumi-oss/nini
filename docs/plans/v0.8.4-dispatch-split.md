## 二、目标架构

### dispatch() 变成 thin match

```rust
pub fn dispatch(state, settings, id, args) -> CommandResult {
    let args = args.trim();
    match id {
        CommandId::Settings => cmd_settings(state),
        CommandId::Model    => cmd_model(state, settings, args),
        CommandId::Tree     => cmd_tree(state),
        // ...
        CommandId::Quit     => cmd_quit(state),
    }
}

// Each command is a private fn:
fn cmd_settings(state: &AppState) -> CommandResult { ... }
fn cmd_model(state: &mut AppState, settings: &mut SettingsManager, args: &str) -> CommandResult { ... }
// ...
```

## 四、风险与缓解

### 风险 1：closure capture 错误

某些 cmd_xxx 可能依赖 dispatch() 内 closure 捕获的变量。

**缓解**：每个 cmd_xxx fn 显式列出所有需要的参数（`state: &mut AppState, settings: &mut SettingsManager, args: &str`），不依赖隐式 capture。

### 风险 2：dispatch() match arm 中有非 cmd_xxx 调用

例如 `CommandId::Status` 调用 `build_status_lines(state)` 这种 helper 已经在其他模块。

**缓解**：dispatch() match arm 只调用 `cmd_xxx(state, settings, args)`，cmd_xxx 内部自己调 helper。

### 风险 3：测试覆盖会发现现有 bug

每个 cmd_xxx 加测试可能发现原有 dispatch() 的边界 bug。

**缓解**：发现 bug 立即修复（不让 v0.8.4 release 拖太久）。
