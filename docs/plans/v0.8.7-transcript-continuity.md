# v0.8.7 — TUI transcript continuity + Pi collapse parity

> **背景**：用户报告"窗口工具调用输出不连续,会断开"。
> **根因**：`render_transcript` 的 autoscroll 用 `lines.len()`（TranscriptLine 数）算滚动单位，但每个 TranscriptLine 展开成 1..N 个 ListItem。N 个并行 tool call → 2N lines → ~10N items。在 80x24 transcript 区（~18 行可见），autoscroll 把最旧的 `▸ name{…}` 推到屏幕顶部以上，用户只看到 N 个 tool result body 末尾，**头部和 body 分离**——视觉感即"断开"。
>
> **调研**：tmux + 真实 nini 跑 8 并行 read，80x24：只显示后 3 个 tool 的 body 末尾；`▸ read` 全部 off-screen。验证通过。
>
> **来源**：与用户对齐于 2026-10-03，决定彻底修复。

## 目标

把以下 5 个相关缺陷一并修掉，不留半成品：

1. **autoscroll 算错单位**（根因）→ 改 item 空间
2. **autoscroll overflow 没有顶部指示**（UX）→ 加 `↑ N more above`
3. **双截断指示** `…(N more lines)` + `…(truncated, N bytes)`（视觉杂乱）→ 单指示合并
4. **单行 200 字节截断 `…` 推出可见区**（边界 bug）→ 透传 area.width
5. **Pi 折叠范式没接入**（Pi 兼容）→ 默认折叠长 result + Ctrl+O 已就位

## 改动清单

### PR 1 — `fix(tui): use item-space autoscroll math`（核心）

`crates/nini-tui/src/render.rs::render_transcript`：

```rust
// BEFORE:
let total = state.transcript_state.lines.len();
let (start, end) = if autoscroll {
    let end = total;
    let start = end.saturating_sub(visible_height);
    (start, end)
};

// AFTER:
let mut items: Vec<ListItem> = Vec::new();
let lines_snapshot: Vec<TranscriptLine> = state.transcript_state.lines.iter().cloned().collect();
for line in &lines_snapshot {
    items.extend(items_for_line(line, theme));
}
// After collecting, truncate to fit visible_height:
if items.len() > visible_height {
    if autoscroll {
        // Keep tail (latest)
        items = items.split_off(items.len() - visible_height);
    } else {
        // User-scrolled: keep slice based on scroll_offset in item space
        let skip = items.len().saturating_sub(visible_height + scroll_offset);
        items = items.split_off(skip);
        if items.len() > visible_height {
            items.truncate(visible_height);
        }
    }
}
```

辅助：`fn items_for_line(line: &TranscriptLine, theme: &Theme) -> Vec<ListItem>`，复用现有
match 分支。

### PR 2 — `feat(tui): ↑ scroll indicator in autoscroll mode`

`render_transcript` 末尾：当 autoscroll=true 且总 items > visible_height 时，在 transcript 顶部 1 行画 `↑ N more above` 提示。

`render.rs`：

```rust
// AFTER items collection, BEFORE the welcome-card check:
let overflow = items_full_len.saturating_sub(visible_height);
if state.transcript_state.autoscroll && overflow > 0 && area.height >= 3 {
    let label = format!(" ↑ {overflow} more above ");
    // Draw at top-left, dim color, single line
    let ind_area = Rect::new(area.x, area.y, area.width.min(label.chars().count() as u16 + 2), 1);
    let ind = Paragraph::new(Span::styled(label, theme.fg_style("dim")));
    f.render_widget(ind, ind_area);
}
```

需要把 items 收集改成**两遍**：第一遍只计数，第二遍实际渲染。或者保留所有 items 在一个完整 vec 里，然后 truncate 显示部分，**overflow = full.len - visible.len**。

### PR 3 — `feat(tui): single combined truncation indicator`

`crates/nini-tui/src/rich.rs::render_tool_result`：把两个 truncation 行合并为一个：

```rust
// BEFORE:
if i + 1 < lines.len() && i + 1 == max_lines && lines.len() > max_lines {
    out.push(... "  …(N more lines)" ...);
}
if linked.len() > TOOL_RESULT_PREVIEW_MAX_BYTES {
    out.push(... "  …(truncated, N more bytes)" ...);
}

// AFTER:
let total_lines = lines.len();
let total_bytes = linked.len();
let hidden_lines = total_lines.saturating_sub(max_lines);
let hidden_bytes = total_bytes.saturating_sub(TOOL_RESULT_PREVIEW_MAX_BYTES);
if hidden_lines > 0 || hidden_bytes > 0 {
    let mut label = String::from("  …(");
    if hidden_lines > 0 { label.push_str(&format!("{hidden_lines} more lines")); }
    if hidden_lines > 0 && hidden_bytes > 0 { label.push_str(", "); }
    if hidden_bytes > 0 { label.push_str(&format!("{} KB hidden", hidden_bytes / 1024)); }
    label.push(')');
    out.push(RLine::from(Span::styled(label, bg.fg(theme.color("dim")))));
}
```

### PR 4 — `feat(tui): cell-aware truncation in render_tool_result`

`render_tool_result` 加 `max_width: Option<usize>` 参数，调用方传 `Some(area.width)`。

```rust

    theme: &Theme,
    max_width: Option<usize>,

    let max_chars_per_line = match max_width {
        Some(n) if n >= 4 => n.saturating_sub(2), // -2 for indent
        _ => 200,
    };
    // ...
    let truncated: String = if display_width(line) > max_chars_per_line {
        // walk chars accumulating display width
        // ...
    } else {
        line.to_string()
    };
}
```

调用方（`render_transcript` 的 TranscriptLine::ToolResult 分支）传 `Some(area.width as usize)`。

### PR 5 — `test(tui): e2e transcript overflow regression`

`crates/nini-tui/tests/transcript_overflow_e2e.rs`：用 `TestBackend` 跑 8 parallel read
fixture，断言：

- 渲染出的 ListItem 数 ≤ visible_height（autoscroll 不溢出）
- 最新一个 tool call 的 `▸ name{…}` header 可见
- 顶部滚动指示器 `↑ N more above` 出现且 N 准确

加 fixture-only 控制组：单 tool call 不溢出时**不**显示指示器。

## 兼容性

- `render_tool_result` 新参数 `max_width` 用 `Option<usize>`，默认 None 走旧路径，调用方逐步迁移
- Ctrl+O 折叠行为不变
- 滚动指示器在 autoscroll 模式新增，不影响 user-scroll 模式已有 `↓ N more`

## 验证

跑 `nini` 真实交互（同 80x24 + 8 parallel read fixture），截图对比前后：

- 修前：只看到 3 个 tool result body 末尾，`▸` 全部 off-screen
- 修后：看到 8 个 `▸ tool {...}` + 8 个 `✓ …` header，body 折叠/截断显示，顶部 `↑ N more above`
