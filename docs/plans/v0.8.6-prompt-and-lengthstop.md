# v0.8.6 — Wire up tool system-prompt + length-stop safety

> **背景**：v0.8.5 修了 TUI 卡死 + 并行读之后，对 Pi v0.85.1 源码做了一次深度调研
> （`docs/research/pi-architecture.md`）。调研发现两个**隐藏多年的 bug**：
> 1. 工具的 `system_prompt_contribution()` 从 v0.7.1 起就在每个 tool 里实现了，
>    `nini-core::build_system_prompt_with_contributions()` 也有，但 **CLI/TUI 从未调用过**。
>    system prompt 一直是硬编码 "Available tools: bash, read, write, edit, grep, find"。
> 2. LLM 因 `output_tokens` 上限被截断（`stop_reason: "length"`）时，
>    末尾的 tool_call JSON 可能被砍掉一半，nini 会把它当合法 JSON parse 后
>    用空参数执行工具。Pi 的处理是整批拒绝。

> **作者**：基于 `docs/research/pi-architecture.md` §3 列出的 P0 项
> **日期**：2026-09-30
> **基于**：v0.8.5 (commit `3bf4815`)
> **计划代号**：v0.8.6-prompt-and-lengthstop

## 1. PR 1 — `fix(cli): wire up build_system_prompt_with_contributions`

### 1.1 问题

`crates/nini-core/src/tool.rs:431` 有现成的：
```rust
pub fn build_system_prompt_with_contributions(
    base: Option<&str>,
    registry: &ToolRegistry,
) -> Option<String> {
    let mut snippets: Vec<(String, String)> = Vec::new();
    let mut guidelines: Vec<(String, String)> = Vec::new();
    for tool in registry.tools() {
        if let Some(contrib) = tool.system_prompt_contribution() {
            if !contrib.snippet.trim().is_empty() {
                snippets.push((tool.name().to_string(), contrib.snippet));
            }
            for g in contrib.guidelines {
                if !g.trim().is_empty() {
                    guidelines.push((tool.name().to_string(), g));
                }
            }
        }
    }
    // 格式化为：
    //   ## Tool self-descriptions
    //   - bash: Run shell commands (ls, grep, cat, cargo test, ...).
    //   - read: Read a file's contents into your context.
    //   ...
    //
    //   ## Tool usage guidelines
    //   - bash: Default for any shell operation; pick this unless...
    //   - bash: Set `timeout` for anything that could run unboundedly.
    //   - bash: Confirm with the user before destructive commands...
    //   - read: Always read a file before editing it...
    //   ...
}
```

每个工具都实现了（`tool.rs:495-498` 测试 + `tool.rs:697` bash 测试）：
- bash: 3 guidelines
- read: 3 guidelines
- write: 2 guidelines
- edit: 3 guidelines

- grep: 2 guidelines

## 2. PR 2 — `fix(core): reject tool_calls on length stop`

### 2.1 问题

`crates/nini-core/src/agent.rs` 的 `run()` 函数（~line 1000+）：

```rust
let mut tool_calls: Vec<PendingToolCall> = Vec::new();
// ... 填充 from SSE stream ...
let message = ...;  // AssistantMessage with stop_reason + content

// ★ 这里没有 length-stop 检查 ★

// 执行 tool calls (v0.8.5: FuturesUnordered)
for (idx, spec) in specs.into_iter().enumerate() {
    futures.push(async move {
        let output = run_single_tool(...).await;
        // ...
    });
}
```

当 `message.stop_reason == "length"`：
- LLM 输出 JSON 可能在 tool_call 部分被砍掉一半（e.g. `{"command": "very long...`）
- `serde_json::from_str(&tc.input_json)` 返回 `Value::Null`（不是错误，是 Null）
- 工具被调用，参数 = null
- 工具内部 `serde_json::from_value::<MyArgs>(args)` 失败 → ToolError::InvalidArgs
- 用户看到一个莫名其妙的 "tool error: invalid args" 错误

Pi 的处理（`agent-loop.js:128`）：
```javascript
const executedToolBatch = message.stopReason === "length"
    ? await failToolCallsFromTruncatedMessage(toolCalls, emit)
    : await executeToolCalls(...);
```

`failToolCallsFromTruncatedMessage` 给每个 tool_call 推一个 `[reject]` 错误。

### 2.2 修复

**位置**：`crates/nini-core/src/agent.rs` 中 `tool_calls` 填完之后、futures 启动之前：

```rust
let mut tool_calls: Vec<PendingToolCall> = Vec::new();
let mut current_call: Option<PendingToolCall> = None;
let mut last_usage = Usage::default();
let mut stop_reason = "end_turn".to_string();

{
    // ... SSE 流的处理（不变） ...
}

// v0.8.6: ★ length-stop 安全门 ★
// Pi 的 agent-loop.js 行为：当 stop_reason == "length" 时，
// assistant message 末尾的 tool_calls JSON 可能被截断（max_tokens 上限）
// —— 如果执行会得到 Value::Null 参数，整批拒绝并继续下一轮。
let truncated_length_stop = stop_reason == "length"
    && tool_calls.iter().any(|tc| !is_valid_tool_call_json(&tc.input_json));

// ... existing push of assistant message ...

if tool_calls.is_empty() { /* 无 tool call 直接 Done */ }

// ★ v0.8.6: length-stop + 有 tool_call 时，整批拒绝 ★
if stop_reason == "length" {
    let mut tool_results: Vec<ContentBlock> = Vec::with_capacity(tool_calls.len());
    for tc in &tool_calls {
        let reject_output = ToolOutput::err(format!(
            "[reject] tool call truncated by output token limit (length stop). \
             The LLM hit max_tokens before serializing the tool call JSON. \
             Retry with a shorter prompt or split the request."
        ));
        yield AgentEvent::ToolResult {
            id: tc.id.clone(),
            output: reject_output.clone(),
        };
        tool_results.push(ContentBlock::ToolResult {
            tool_use_id: tc.id.clone(),
            content: reject_output.content,
            is_error: true,
        });
    }
    self.messages.push(Message {
        role: Role::Tool,
        content: tool_results,
        timestamp: 0,
    });
    self.set_phase(AgentPhase::Idle);
    yield AgentEvent::TurnEnd { ... };
    yield AgentEvent::PhaseChanged(AgentPhase::Idle);
    continue;  // 让 agent 跑下一轮，让 LLM 自己 recover
}

// 正常路径：v0.8.5 FuturesUnordered
// ...
```

async fn length_stop_with_tool_calls_rejects_all() {

## 3. PR 3 — `enhance(skills): include file location in prompt`

### 3.1 问题

`crates/nini-core/src/skills.rs:166` 当前输出：
```
The following skills provide specialized instructions for specific tasks.
Use the read tool to load a skill's file when the task matches its description.
When a skill file references a relative path, resolve it against the skill directory.

- beautiful-article: 把用户提供的素材...
- firecrawl: Search, scrape, and interact...
```

Pi (`skills/skills.ts:355`) 输出：
```
The following skills provide specialized instructions for specific tasks.
Use the read tool to load a skill's file when the task matches its description.
When a skill file references a relative path, resolve it against the skill directory (parent of SKILL.md / dirname of the path) and use that absolute path in tool commands.

<available_skills>
  <skill>
    <name>beautiful-article</name>
    <description>把用户提供的素材...</description>
    <location>/home/jin/.pi/agent/skills/beautiful-article/SKILL.md</location>
  </skill>
  <skill>
    <name>firecrawl</name>
    ...
    <location>/home/jin/.pi/agent/skills/firecrawl/SKILL.md</location>
  </skill>
</available_skills>
```

**差距**：nini 的模型知道 skill 的 name + description，但**不知道文件路径**，所以无法用 `read` 实际加载 skill 内容。skill 永远不会被触发。

### 3.2 修复

```rust
// crates/nini-core/src/skills.rs::format_skills_for_prompt
pub fn format_skills_for_prompt(skills: &[Skill]) -> String {
    let visible: Vec<&Skill> = skills.iter().filter(|s| !s.disable_model_invocation).collect();
    if visible.is_empty() {
        return String::new();
    }
    let mut out = String::from(
        "\n\nThe following skills provide specialized instructions for specific tasks.\n\
         Use the read tool to load a skill's file when the task matches its description.\n\
         When a skill file references a relative path, resolve it against the skill directory.\n\
         \n\
         <available_skills>\n",
    );
    for s in visible {
        // v0.8.6: add <location> so the model can `read` the file to load the skill
        out.push_str(&format!(
            "  <skill>\n    <name>{}</name>\n    <description>{}</description>\n    <location>{}</location>\n  </skill>\n",
            xml_escape(&s.name),
            xml_escape(&s.description),
            xml_escape(&s.file_path.display().to_string()),
        ));
    }
    out.push_str("</available_skills>\n");
    out
}

fn xml_escape(s: &str) -> String {
    s.replace('&', "&amp;").replace('<', "&lt;").replace('>', "&gt;").replace('"', "&quot;")
}
```

## 6. 风险

| 风险 | 缓解 |
|---|---|
| PR 1 改动函数签名，影响 3+ 调用点 | 完整 grep 找到所有调用；一次性更新；测试覆盖 |

| PR 3 skill prompt 改 XML 格式，破坏旧 prompt parser | nini 没 parser，但 e2e 测试要验证模型仍能识别 skill |
