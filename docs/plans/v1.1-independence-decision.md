# 决策记录：从 v1.1 起，nini 脱离 Pi 0.85.1 对标，自行进化发展

> 决策日期：2026-11-22
> 决策人：owner
> 状态：**已决策**（本文件为该决策的权威记录）

## 1. 决策原文

**从 1.1 版本开始，nini 项目脱离 Pi 0.85.1 对标，自行进化发展。**

## 2. 含义界定

「脱离对标」指：**nini 不再以 Pi 0.85.1 的行为作为设计目标与正确性判据**。
此前「nini = Pi 0.85.1 的 clean-room Rust 重写」的定位终止，自 v1.1 起 nini 是
**自主演进的独立项目**，功能、行为、交互由 nini 自己的目标与需求决定。

具体分三层界定：

| 层 | 此前的约束 | v1.1 起的口径 |
|---|---|---|
| **行为层**（agent loop、TUI 渲染、工具、hooks、命令语义） | 以 `references/pi-0.85.1/` 快照为行为 oracle，逐符号对齐 | **终止对标**。nini 自行设计；Pi 快照仅作历史参考，不再是正确性判据 |
| **文件格式层**（session JSONL、settings、slash 命令、skills、compaction 格式） | 以 `references/spec-v0.85.1/` 为格式真相 | **保留兼容性为默认**（用户数据与生态资产），但兼容是「成本合理的选择」而非「必须对齐的约束」；格式演进自主决定 |
| **验证资产**（`pi-oracle-lock.py`、conformance fixtures、parity-gaps 台账、`pi-target-lock.py`） | 冻结期内的机器门禁，oracle 必须存在且不漂移 | **降级为历史基线**：快照与 fixture 保留在仓库（不可逆删除无收益），但不再作为 v1.1+ 的进化约束；新功能的判据改为 nini 自建 oracle |

## 3. 动机

1. **对标已到收益饱和点**：`scripts/parity-gap.py` 台账已关账（fixed 48 / fake 10 / open 0），
   行为层对齐 Pi 0.85.1 的欠账已清；继续以 Pi 为锚，只会让 nini 的自主设计被一个
   冻结版本的边界框住。
2. **自主进化的领域需要空间**：子代理等能力 Pi 0.85.1 没有，若继续挂「对齐 Pi」的
   目标，每项新功能都要先论证「Pi 没有所以不算偏离」——目标与能力自相矛盾。
3. **冻结 oracle 的维护成本**：`pi-oracle-lock --verify-refs` 的符号锁、行号漂移检查，
   在对标终止后不再是门禁，保留其执行只会增加无意义的约束与返工。

## 4. 对既有资产与文档的影响（需联动更新）

以下文档/机制的表述建立在「对标 Pi 0.85.1」之上，v1.1 开发启动时应同步修订：

| 资产 | 当前状态 | v1.1 起的处理 |
|---|---|---|
| `docs/GOALS.md` §T1（对照物唯一版本 0.85.1） | 权威目标常量 | 改写为 v1.1 自主演进目标；T1 的冻结纪律废止，保留为历史章节 |
| `README.md` / `README.zh-CN.md` 中「re-implementation against Pi v0.85.1's pinned behavioral oracle」等定位表述 | 对外定位 | 改为自主演进定位；保留「历史基线参考」的说明 |
| `scripts/pi-oracle-lock.py`、`scripts/pi-target-lock.py`、`scripts/pi-session-record.sh` | 对标门禁 | 保留文件（历史资产），从 CI/门禁执行中摘除 |
| `crates/nini-conformance/`（Pi 会话 fixture、parity 测试） | oracle 测试 | 保留为回归基线；新功能不要求 Pi 对照 |
| `scripts/parity-gaps.json` 台账 | 差距台账（已关账） | 冻结为历史记录，不再更新 |
| `docs/plans/parity-with-pi.md`、`tool-parity.md`、`next-parity.md` 等对标计划 | 执行细则 | 标注为「v1.1 前历史文档」，不再作为新工作依据 |
| `CHANGELOG.md` 版本号 | v1.0.4 | 下一版本从 **v1.1.0** 起，版本号自主演进 |

**不做的事**：不删除 `references/pi-0.85.1/` 与 `references/spec-v0.85.1/` 快照
（删除不可逆，且历史参考仍有价值）；不做一次性大改写，随 v1.1 各项开发逐步同步表述。

## 5. 对子代理升级的直接影响

1. **无对齐负担**：子代理是 Pi 没有的能力，v1.1 起无需论证「为何 Pi 没有、是否偏离」，
   按 nini 自身需求自由设计。
2. **无参考实现可抄**：仍需自设计自实现，但设计目标是 nini 自身的可用性、一致性与
   可判定性，不再受 Pi 行为边界约束。
3. **测试策略改变**：不再以「Pi 无此能力」为豁免理由；子代理的验收判据是 nini 自建的
   oracle（fixture provider 驱动的端到端测试、契约测试、变异注入），conformance 层的
   Pi fixture 不适用于子代理。
4. **命名与语义自主**：子代理工具的命名（`task`/`agent`/`delegate`）、参数 schema、
   事件呈现、并发策略均按 nini 自身口径设计，无需为 Pi 的拼写/语义让路。

详见 `docs/plans/subagent-research.md`（调研报告，已同步本决策）。

- v1.0.x 的对标纪律不追溯、不改动已发布产物与已关账台账。
