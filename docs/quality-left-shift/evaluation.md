## 二、效率

本节从效率维度评估 Quality Left-Shift 方案引入 niN 的增益方向与可控性。

**一、理论效率增益**
质量左移将质量防线前移至变更与写工具层，在改动进入完整流程与多轮验证之前即实施拦截，从而减少无效轮次：坏改动在进入后续流程前被拦截，避免不必要的 review 与返工，并使验证前置。因此本方案带来的增益属效率型增益，而非算力或吞吐提升，与方案评估口径一致，核心是减少 LLM 无效调用与 token 消耗，降低为达成质量所付出的额外运行成本。

**二、实际效率数据**
当前尚无运行时效率实测。AC8 性能指标处于待采样状态，无效轮次与总轮次等关键效率数据尚未采集，故本方案的实际效率提升目前未量化验证，现有证据不足以给出具体数值；效率收益的量化需待样本周期采集完成后进行。

**三、效率可控性**
本方案将拦截门放在变更/写工具层，不占用 agent loop 热路径，不增加每轮执行延迟；静态检查成本较低；阶段3 的局部形式化与发版门红队按局部化设计组织，不会全面摊派验证负担。综上，效率增益具备可兑现条件，且对执行延迟的影响可控，不会以明显延迟代价换取质量收益。

**四、结论**
从方向判断看，引入 niN 配合质量左移属于正向效率改进：以更前置、更局部的拦截降低无效调用与运行成本，方向明确。当前效率评估的方向基于方案口径与架构事实作出；实际效率提升数值为待采样项，不虚构实测数据，待 AC8 样本周期采集完成后可进一步量化验证。
